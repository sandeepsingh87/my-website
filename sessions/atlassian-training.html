🕐 Timeline

The 8-Year Journey — What was built when?

The engineer built several major systems over 8 years. Here is the complete journey, step by step, in simple language.

Year 0 · The Interview
Getting Hired at Atlassian
Interview had 3 rounds: (1) HackerRank coding test — aced with full marks. (2) Technical round — given a Cloudflare whitepaper to read, then asked about microservices and containers. (3) Troubleshooting round — debugged a real Atlassian denial-of-service incident. Values interview — he asked: "12 months from now, what would I need to achieve for you to say hiring me was a good decision?" — This impressed the interviewer greatly. He was hired to build a self-service load balancing web app.
Year 0–2 · Foundation
Building the Open Service Broker (OSB)
First major project: Build an API-based web app that lets developers self-provision resources (like load balancers) without asking the infra team. Used Python (Connexion → Flask → FastAPI). Added async worker via SQS queue + DynamoDB. Deployed proxies via AWS CloudFormation across 13 regions. Created custom AMI using Packer + SaltStack.
Year 2–3 · Core Product
Envoy Control Plane — "Sovereign"
Built a management server for Envoy Proxy (open-sourced on Bitbucket as "Sovereign"). It dynamically generates proxy configuration from templates + live data. No need to manually configure each proxy. Jira, Confluence, Bitbucket, StatusPage all went behind this system.
Year 3–5 · Scale
Migrating All Atlassian Products
Big migration project — moved ALL Atlassian microservices behind the new centralized load balancing infrastructure. Improved security (no accidental public exposure) and saved millions in enterprise load balancer licensing costs. Added sidecar services for: Authentication (in Rust), Authorization, and Rate Limiting.
Year 5–8 · Maturity
Features, Compliance & Growth
Added advanced Envoy features: external auth, external processing filters. Went through compliance and security auditing. Grew non-technical skills: diplomacy, conflict resolution, mentoring, persuasion. Then laid off in Atlassian's company-wide layoffs affecting ~500 employees.

⚙️ Key Components

The 5 major things he built — explained simply

Each component solves a specific real-world problem. Let us go through each one.

📋

1. Open Service Broker (OSB)

Problem: Developers had to manually ask the infra team to set up load balancers. Very slow process!

Solution: Self-service API app where devs commit a JSON config file to Bitbucket, and the system automatically provisions everything — DNS, CloudFront, load balancers.

FastAPIDynamoDBSQSPython
🧠

2. Sovereign — Envoy Control Plane

Problem: With 2,000 proxy servers running, how do you update their config without restarting each one?

Solution: "Sovereign" — a management server that reads templates + live data, then pushes updated configurations to all Envoy proxies in real-time. Open-sourced on Bitbucket!

Envoy xDS APIJinja2 TemplatesFastAPI
🖼️

3. AMI Image Pipeline

Problem: How do you make sure all 2,000 proxy servers have exactly the same software and security settings?

Solution: Used HashiCorp Packer + SaltStack to build a "golden image" (AMI) with Envoy, logging, security hardening, network tuning, and observability. CloudFormation uses this AMI to spin up all servers.

PackerSaltStackCloudFormationEC2
🔐

4. Authentication Sidecar

Problem: Every backend team (Jira, Confluence, Bitbucket…) was implementing authentication themselves — massive duplication!

Solution: Built a sidecar container (in Rust) that runs alongside each Envoy proxy and handles authentication centrally. All backend services get auth automatically — for free.

RustSidecar Patternext_authz
🛡️

5. Security & Rate Limiting

Problem: DoS attacks, bots, and abusive API users were hitting backend services directly.

Solution: DoS protection via AWS CloudFront. Rate limiting via a separate sidecar. Access logs centralized at proxy layer — all handled BEFORE requests reach Jira/Confluence backends.

CloudFrontRate LimitingAccess Logs
🔄

6. AWS Infrastructure (CloudFormation)

What was provisioned: VPC, Subnets, Internet Gateway, Security Groups, IAM Roles, Auto Scaling Groups, EC2 instances, NLB, ACM certificates, Route 53 DNS records.

Scale: ~2,000 Envoy proxy servers across 13 AWS regions globally.

VPCASGEC2Route53ACM

Why Centralize? — The Cost Saving Argument

Imagine 1000 dev teams each implementing authentication separately — that is 2000 engineer-months wasted! With centralized auth at the proxy layer, it is done ONCE and all teams benefit automatically. Same for rate limiting, DoS protection, SSL/TLS. This is the core value of Platform Engineering.

🎓 Lessons Learned

What did 8 years at Atlassian teach him?

These are the REAL lessons — both technical and human. Very relevant for your QA and Engineering teams too!

🔧 Technical Lessons

When you build something, think about the person who will maintain it 2 years later (it might be YOU!). Write good documentation. Add monitoring. Make failure states obvious. The "curse of knowledge" means what is obvious to you now will be confusing to others later.

For your QA team: This is why test documentation, test data management, and automation framework readability matter so much!

He started with Connexion → moved to Flask → moved to FastAPI. He did not over-engineer on day 1. Requirements became clearer as he built and learned. This is called "evolutionary architecture."

  • Do not build for imaginary future requirements
  • But leave room to grow using clean interfaces
  • Refactor regularly as you learn more

The OSB uses async pattern: API receives request → drops task into SQS queue → worker picks it up → updates DB → client polls for result. This prevents the API from blocking while slow operations happen.

Desi analogy: Like ordering on Zomato — you get "order confirmed" immediately, but food is still being prepared. You keep refreshing to check status!

By centralizing auth, rate limiting, logging, and SSL at the proxy layer — Atlassian saved thousands of engineer-hours. Every new service automatically got these features for free.

  • Centralize cross-cutting concerns
  • Let application teams focus on business logic
  • Platform teams handle infrastructure concerns

Everything was defined in code (CloudFormation, Packer, SaltStack). Same infrastructure can be recreated in any AWS region in minutes. No manual clicking in AWS console. No "works only in one region" surprises!

🤝 Soft Skill Lessons

Working with multiple teams (security, platform, Jira, Confluence) requires navigating disagreements professionally. Not every battle is worth fighting. Choose where to push hard and where to compromise.

For QA leaders: When raising bugs or process issues — frame it as "how can we improve?" not "you made a mistake."

Great ideas die without good communication. He learned to propose ideas in a structured way — explaining the problem, the solution, trade-offs, and expected outcome.

  • Use data to back your proposals
  • Show the cost of NOT doing something
  • Get stakeholder buy-in early

As the team grew, he had to onboard new members, write runbooks, create documentation, and train people on complex systems. The ability to explain technical concepts simply is a very high-value skill.

This is exactly what you are doing with this training module! 🎯

Security audits, compliance checklists, FedRAMP/SOC2 requirements — all are tedious but protect the company and customers. He found this boring but acknowledges it is essential. Not all work is exciting!

He was part of Atlassian's ~500-person layoff. Instead of being bitter, he created a thoughtful educational video sharing his knowledge. That is a powerful professional response.

  • Keep your LinkedIn updated always
  • Document your achievements as you go
  • Build your personal brand proactively

🌟 Top Takeaways for Your Engineering Team

Self-Service is the Goal

Great platforms let developers provision and configure things themselves — without raising tickets or waiting for another team.

Abstract the Complexity

Developers send simple JSON config. The platform handles all complex AWS, Envoy, DNS configuration behind the scenes.

Solve Problems Once

Auth, rate limiting, logging — solve them at the platform level once. Do not make 100 teams solve the same problem 100 times.

Dynamic > Static Config

Sovereign's dynamic configuration model meant zero downtime for config changes. Always prefer runtime configurability.

Open Source What You Can

He open-sourced "Sovereign" on Bitbucket. Sharing knowledge builds reputation and gets community contributions.

Ask the "12-Month" Question

In any new role, ask: "12 months from now, what would I need to achieve for this to be a success?" — aligns expectations immediately.
